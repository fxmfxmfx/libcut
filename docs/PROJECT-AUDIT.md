# Аудит и проверка libcut 2.0

Проверены хранение client/local данных, API TikTok, поиск, плеер, комментарии, доставка медиа, конфигурация и сборка. Это отчёт об исследованных сценариях и найденных дефектах; он не гарантирует отсутствие всех возможных ошибок.

## Исправленные проблемы

| Область | Дефект исходной версии | Исправление |
| --- | --- | --- |
| Настройки клиента | Серверные значения могли примениться до загрузки DATA_MODE; autoMarkSeen не сохранялся | Загрузка режима до синхронизации, миграция старых ключей, сохранение всех предпочтений |
| Хранилище | Ошибки чтения/записи не объяснялись пользователю; вкладки перезаписывали устаревшее состояние | Проверка формата, сообщения об ошибках, экспорт исходных повреждённых данных, синхронизация вкладок |
| Лента клиента | GET автора возвращал старые видео; каждое изменение просмотренного снова запрашивало все подписки | Обновление публичного кэша, отдельный query-кэш ленты, локальная фильтрация просмотров |
| Статусы видео | Ручная отметка в client режиме меняла серверную БД; компоненты подписывались на неизменную функцию проверки | Локальные действия и реактивные массивы, совместимость старых ID и стабильные TikTok ID |
| Поиск | scrapeSearch был заглушкой; live-видео не всегда имели существующий ID | Браузерный подписанный поиск, быстрый поиск в своей библиотеке, устранение дублей, сохранение публичных метаданных |
| Телефон | Комментарии зависели от нескольких вложенных областей прокрутки | Переключение видео/комментариев, доступная прокрутка и закрытие, safe-area отступы |
| Медиа | Отсутствовал маршрут скачивания; suffix/ошибочные Range обрабатывались неверно | Attachment-маршрут, 206/416, backpressure, общая и атомарная загрузка файла |
| Backend | Блокирующий curl, неограниченные параллельные задачи, частичная замена комментариев | Асинхронные процессы, очереди и дедупликация, лимиты/таймауты, транзакционная замена |
| Прокси | Chromium пропускал URL с авторизацией и не учитывал runtime-настройку | Loopback-мост proxy-chain, передача текущего прокси в сервис, запрет тихого обхода |
| Изоляция | Client API мог читать/менять общие личные данные; ответ настроек содержал пароль прокси | Запрет серверных personal API в client режиме, маскировка секретов, локальный поиск по данным браузера |
| Развёртывание | Caddy принимал порт upstream из query; не было согласованного standalone-запуска | Удалён произвольный port-forward, loopback по умолчанию, контроль обоих процессов и readiness |
| Кэш и метаданные | Повторное извлечение метаданных при каждом открытии и файлы без записей в БД | TTL метаданных, очистка осиротевших файлов с запасом времени для активной загрузки |

## Проверки

- `bun run check`: ESLint, TypeScript и 33 регрессионных теста основного приложения.
- В `mini-services/tiktok-comments`: `bun run typecheck` и `bun run test` — 5 тестов разбора ответов поиска.
- `bun run test:upgrade`: реальное обновление временной SQLite со старой схемы сохраняет подписку, просмотр, избранное и настройку.
- `bun run build`: standalone production-сборка Next.js.
- `bun run test:e2e`: четыре применимых браузерных сценария на временных базах; client/local поиск → профиль → плеер → мобильные комментарии → скачивание, сохранение клиентских данных и синхронизация вкладок. Два повтора client-only сценариев в local проекте намеренно пропускаются.
- Chromium/Puppeteer запускается; сервис отклоняет нетиктоковские и локальные URL и некорректные параметры.
- Live-проверка без прокси в текущей сети: поиск `coffee` вернул 12 видео; поиск авторов — 10 авторов. Это разовая проверка, а не гарантия доступности из другой сети.
- На выбранных live-видео TikTok показал «Video currently unavailable» / не вернул API комментариев. Проверена обработка этой ошибки; успешная загрузка live-комментариев в этой сети не подтверждена. Мобильное отображение проверено на demo-комментариях.

Docker локально отсутствует. [Первая сборка образа в CI прошла](https://github.com/fxmfxmfx/libcut/actions/runs/39725236121/job/119647507512). В CI также добавлен запуск готового контейнера с проверкой обоих сервисов, ленты и скачивания; актуальный результат доступен во вкладке Actions. Локальная проверка entrypoint ограничена shell-синтаксисом. CI запускает проверки приложения и браузерные сценарии.

## Зависимости и оставшиеся ограничения

Исходный lockfile основного проекта имел 111 advisories. После обновления и удаления неиспользуемых пакетов `bun audit` сообщает **две high**: `braces` в цепочке ESLint и `deepmerge-ts` в CLI Prisma. Они остаются в инструментах сборки/управления схемой; не следует подавать им недоверенные конфигурации. Совместимое обновление не устраняет эти две зависимости; принудительная смена major ради подавления отчёта не применялась. Аудит браузерного сервиса не нашёл уязвимостей на момент проверки.

В приложении нет аутентификации. Режим `local` предназначен для доверенной сети. В `client` личное состояние остаётся в браузере, а публичные метаданные, комментарии и медиа-кэш всё ещё общие. Это не полностью изолированный многопользовательский хостинг.

Live-функции зависят от региона, captcha, доступности TikTok, прокси и актуальности yt-dlp/Chromium. Короткие TikTok-ссылки пока нужно раскрывать до полного адреса вручную. Удалённые видео и потерянные данные браузера без резервной копии приложение восстановить не может.
