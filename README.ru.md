# libcut 2.0

Собственный просмотрщик TikTok: подписки, лента непросмотренных видео, избранное, комментарии, скачивание и фотогалереи. Аккаунт TikTok не требуется. В интерфейсе есть русский и английский языки, шесть тем, выбор акцента и пользовательский CSS.

**Используйте приложение на своём компьютере или в доверенной сети. Авторизации нет.** Client режим хранит личные данные в браузере, но не превращает приложение в защищённый публичный сервис. Уважайте авторские права и условия TikTok.

## Запуск в Docker Compose

```sh
git clone https://github.com/fxmfxmfx/libcut.git
cd libcut
cp .env.example .env
# Проверьте настройки .env:
docker compose up -d --build
```

Откройте **http://localhost:3000**. По умолчанию включены demo mode и доступ только с текущего компьютера. Для настоящего TikTok укажите в `.env`:

```dotenv
DEMO_MODE=false
TIKTOK_PROXY=socks5://адрес-прокси:1080
DATA_MODE=local
```

Поддерживаются SOCKS5 и HTTP(S), включая авторизацию. Специальные символы в логине/пароле нужно кодировать как URL. Для доступа из **доверенной домашней сети** задайте `LIBCUT_BIND` равным LAN-адресу компьютера либо `0.0.0.0`, если это соответствует вашей конфигурации. Не открывайте порт в публичный интернет.

```sh
docker compose logs -f libcut
docker compose ps
docker compose down
```

База и кэш находятся в именованных томах. **Команда `docker compose down -v` удаляет их.** Внутренний браузерный сервис слушает только loopback:3040; наружу публикуется порт 3000.

## Где хранятся данные

| Режим | Личные данные | Общие серверные данные |
| --- | --- | --- |
| `local` | SQLite: подписки, избранное, просмотры, настройки; доступны всем посетителям | Метаданные, комментарии, медиа-кэш |
| `client` | localStorage текущего браузера: подписки, избранное, просмотры, настройки | Публичные метаданные TikTok, комментарии, медиа-кэш |

В client режиме другой браузер, устройство, домен или порт означают отдельную библиотеку. Сохраняйте JSON через **Настройки → Экспортировать резервную копию** и используйте импорт для переноса. Не очищайте данные сайта без копии. Сервер не отдаёт клиенту общие подписки, избранное, просмотры или пароль прокси.

Локальный поиск в client режиме использует собственные подписки, избранное и уже загруженные в браузере сведения. Общая серверная библиотека не перечисляется.

## Просмотр ленты

Подпишитесь на авторов и откройте **Ленту**. Листайте вверх на телефоне, прокручивайте мышью/трекпадом или установите фокус на ленту и нажимайте **↑ / ↓**. На компьютере доступны кнопки переключения. Нажатие на видео ставит его на паузу. Звук изначально включён; громкость регулируется ползунком и кнопкой динамика. Если браузер блокирует автозапуск со звуком, нажмите воспроизведение. Громкость и выключение звука сохраняются в браузере и используются и в ленте, и в плеере.

Видео из поиска, избранного и профиля автора открываются в том же вертикальном плеере. Листайте текущую подборку; нижний ползунок перематывает видео, кнопка закрытия возвращает назад.

Комментарии открываются поверх ленты и останавливают воспроизведение. Рядом с роликом доступны избранное, скачивание и отметка просмотра. Автоматическая отметка ставится во время воспроизведения; ролик остаётся в текущей очереди, чтобы можно было вернуться назад. При следующем открытии ленты просмотренные ролики скрываются. В local режиме следующие страницы подгружаются по мере просмотра.

## Поиск и ограничения TikTok

Можно искать по словам и `@нику`, вставлять полную ссылку вида `https://www.tiktok.com/@username`, `/@username/video/ID` или `/photo/ID`. Короткие ссылки `vm.tiktok.com` не разворачиваются: откройте такую ссылку и скопируйте полный адрес.

Поиск TikTok и комментарии требуют Chromium-сервис. Региональные ограничения, captcha и блокировки TikTok могут мешать запросам даже при исправном приложении. Ошибки показываются в интерфейсе; проверьте прокси и логи. Проверки в demo mode не подтверждают работу конкретного прокси.

## Локальная разработка и проверки

Нужны **Node 22+** и **Bun 1.3+**. В live режиме дополнительно требуются `curl`, `ffmpeg`, Python с `yt-dlp` и `curl_cffi`, а для поиска и комментариев — Chromium.

```sh
cp .env.example .env
mkdir -p db
export DATABASE_URL="file:$(pwd)/db/custom.db"
export TIKTOK_CACHE_DIR="$(pwd)/cache/videos"
bun install --frozen-lockfile
bun run db:generate
bun run db:push
bun run dev
```

Для постоянной конфигурации сохраните абсолютные пути в `.env`. Для локального production-запуска абсолютный путь SQLite обязателен. В demo mode ни Chromium, ни yt-dlp не нужны.

Во втором терминале для live-поиска и комментариев:

```sh
cd mini-services/tiktok-comments
PUPPETEER_SKIP_DOWNLOAD=true bun install --frozen-lockfile
bunx puppeteer browsers install chrome
bun run dev
```

Браузерный сервис собирается Bun и запускается Node.js: `bun run build && bun run start` в `mini-services/tiktok-comments/`. После изменения TypeScript пересоберите сервис; `bun run dev` следит за готовым JavaScript. Для HTTP CONNECT используется Node.js.

Пример systemd-службы: [libcut-comments.service](scripts/systemd/libcut-comments.service). Он рассчитан на пользователя `libcut`, файлы в `/opt/libcut` и настройки `/etc/libcut.env`; создаёт доступные для записи HOME/XDG-каталоги, необходимые Chromium.

Вместо загрузки Chromium можно указать путь к системному браузеру через `PUPPETEER_EXECUTABLE_PATH`. Приложение передаёт сервису текущую настройку прокси.

```sh
bun run check      # ESLint, TypeScript, регрессионные тесты
bun run build      # production-сборка
bun run start      # запуск готовой сборки
bunx playwright install chromium
bun run test:e2e   # браузерные проверки обоих режимов после build
```

Standalone-сборку разворачивайте в чистом каталоге и переключайте сервис на него. Не распаковывайте её поверх старой: оставшиеся файлы сборки могут вернуть старый интерфейс. Настройки окружения, базу, кеш видео и сервис комментариев сохраняйте отдельно.

Браузерные проверки создают отдельные временные базы. Параметры окружения описаны в [.env.example](.env.example) и [английском README](README.md#configuration). `.env` и пароли не должны попадать в Git. Внешние `url()` и `@import` в пользовательском CSS отключены.
